

# 關於占卜師，請讓opecclaw自行學習紫微斗數，易經，西洋占星，塔羅牌等占卜技術，依此基礎讓用戶選擇偏好占卜師，並依據不同占星技巧維護用戶資料，考證追蹤，以及意見格式

先用產品設計的角度講結論：可以把「占卜師代理人」設計成一個多技能 Agent（紫微斗數、易經、西洋占星、塔羅），核心是「共用一份用戶主檔 + 各占卜技術自己的子資料結構 + 統一的占卜紀錄與追蹤格式」。


***

## 1. 系統整體架構概念

- 一個「占卜師主 Agent」（例如：opecclaw-FortuneTeller），內含 4 組子技能：
    - Zi Wei Dou Shu Skill（紫微斗數）
    - I-Ching Skill（易經）
    - Western Astrology Skill（西洋占星）
    - Tarot Skill（塔羅）
- 共用一份 User Profile（包含基本資料 + 心理 / 生命議題標籤），每次占卜再寫入對應技術的子紀錄。這個做法類似 Zi Wei Dou Shu 分宮位、但以系統層面抽象成不同模組。
- 所有占卜結果用一個「標準占卜紀錄格式」存起來，方便後續「考證追蹤」（驗證準確度）與意見回饋分析。

***

## 2. 用戶主檔資料設計（共用部分）

建議的 User Profile 結構（Pseudo Schema）：

- 基本資料
    - user_id
    - 姓名 / 暱稱
    - 性別（含非二元選項）
    - 語言（zh-TW / en）
- 出生資訊（給紫微 + 西洋占星用）
    - 西曆出生日期（yyyy-mm-dd）
    - 出生時間（hh:mm，是否精確）
    - 出生地（城市 + Country，未來可用時區修正）[^3]
- 占卜偏好
    - 偏好占卜系統：ZiWei / IChing / Western / Tarot（多選權重）
    - 接受的風格：直白 / 溫和 / 勸導型 / 實務建議型
    - 接受預言時間尺度：短期（3 個月）、中期（1 年）、長期（3 年以上）
- 生活主題標籤（跨技術共用）
    - 感情、婚姻
    - 職涯、工作變動
    - 財務、投資
    - 家庭、人際
    - 身心健康、精神壓力
- 風險 \& 邊界
    - 是否有身心疾病或重大壓力註記
    - 禁止觸及的題目（例如：死亡時間、疾病診斷、彩票號碼等）

這份主檔是所有占卜技術的共同基礎，ZWD / Astrology 在生成命盤時使用 DOB/Time/Place，易經與塔羅則主要用在語氣與情境解讀。

***

## 3. 各占卜技術專屬資料設計

### 3.1 紫微斗數模組

紫微需要比較完整的命盤結構；專利與教學文章裡，基本都包含：個人資料 → 生成命盤 → 十二宮位＋星曜。你可以抽象成：命盤快照 + 解讀索引。

- 基本欄位
    - ziwei_chart_id
    - user_id
    - 命盤生成時間（用來區分「本命盤 / 大限盤 / 流年盤」）
    - 命盤類型：本命 / 流年 / 流月 / 問事占卦（若走牌卡式紫微占卜）[^8]
- 命盤核心結構（可 JSON）
    - 十二宮陣列（命、兄弟、夫妻、子女、財帛、疾厄、遷移、僕役、官祿、田宅、福德、父母）
    - 每宮星曜列表（主星、輔星、煞星、祿權科忌等）[^1][^6]
    - 天干地支、身宮、四化
- 關聯標籤
    - 此命盤主要應用領域（例如：感情、職涯）
    - 系統生成的重點宮位（如命、財、官、夫妻）標記，方便後續問事快速引用

如果走「紫微牌卡占卜」那一路，可以多加「占卜牌陣 / 抽牌結果」，讓零基礎使用者也能使用紫微問事。

***

### 3.2 易經模組

參考市面 I-Ching API 的做法，最重要是「卦象 + 動爻 + 變卦 + 詮釋」。

- iching_reading_id
- user_id
- 問卦時間
- 問卦類型：一般 / 感情 / 職涯 / 財務 / 健康（方便日後統計）
- 占卜方式：三錢法 / 六爻蓍草 / 系統亂數
- 本卦資訊
    - 本卦編號（1–64）
    - 本卦名稱（乾、坤…）
    - 上卦 / 下卦
- 動爻與變卦
    - 動爻位置列表（1–6）
    - 變卦編號 \& 名稱
- 系統解讀
    - 傳統義摘要（卦辭、爻辭的現代語意）
    - 現代化建議（愛情 / 職涯 / 決策面向）
    - 行動建議（1–3 條可執行建議）

***

### 3.3 西洋占星模組

西占常見設計：本命盤（Natal Chart）+ 12 宮、行星落點、Aspect、Transits。[ 類似處理方式可套用在西占]

- astro_chart_id
- user_id
- Chart 類型：Natal / Transit / Solar Return / Relationship（合盤）
- 基本資料
    - 生成時間（系統）
- Chart 結構
    - 12 宮：每宮主題 + 宫頭星座
    - 行星落點：行星 → 星座 → 宮位
    - 相位列表：行星1、行星2、角度類型（合相、沖、拱、刑…）
- 系統解讀（可拆模塊）
    - 性格重點（太陽、月亮、上升）
    - 情感模式（⦿ 金星，⦿ 月亮組合）
    - 職涯傾向（中天、土星、火星等）

***

### 3.4 塔羅模組

可參考現有塔羅排陣紀錄模版：每次占卜一筆 Session，包含問題、牌陣、每張牌的位址與正逆位、解讀摘要與行動建議。

- tarot_session_id
- user_id
- 占卜時間
- 牌陣類型
    - 單張（今日指引）
    - 三張（過去 / 現在 / 未來）
    - 十字 / 大十字 / 關係牌陣 …等
- 問題（原文）
- 抽牌結果（Array）
    - 牌名（Major / Minor，包含花色與數字）
    - 正位 / 逆位
    - 位置意義（如「過去」、「阻礙」、「建議」）
- 系統解讀
    - 每張牌解讀摘要
    - 整體故事線 / 統整訊息
    - 建議行動（具體 2–3 點）

## 4. 共通「占卜紀錄」與考證追蹤設計

為了讓 opecclaw 可以做「驗證 \& 追蹤準確度」，建議每一次占卜（不管用哪種技術）都寫進一個統一表格，例如「DivinationSession」。

### 4.1 占卜紀錄基本欄位

- session_id
- user_id
- method（ZiWei / IChing / Western / Tarot / Mixed）
- 問題描述（user 原文 + 系統重寫版）
- 關聯主題標籤：感情 / 職涯 / 財運 / 健康 / 其他
- 預測時間範圍：例如「未來 3 個月」、「一年內」、「本週」
- 關鍵預測點（Normalized）
    - 比如：升遷機率 ↑、分手風險 ↑、財務壓力 ↓…（用半結構化欄位方便日後統計）
- 建議行動清單（list of 建議）


### 4.2 考證追蹤欄位（Follow-up）

之後用戶回來，可以讓 Agent 問：「上次我們講的 A/B/C 結果如何？」讓用戶回填。

- verification_status
    - 未回覆 / 部分應驗 / 明顯應驗 / 未發生 / 相反發生
- 用戶回饋文字
- 系統結論：
    - 這次占卜準確度評分（1–5）
    - 誤差原因（時機 / 用戶行動改變 / 解讀偏差）

這種設計對日後做「模型微調」或 Prompt 優化很重要，類似 I-Ching API 或各種占卜服務搞的「用戶回饋 / 評分機制」。

## 5. 意見格式與 UX 建議（中英雙語）

為了配合你「讓用戶選擇偏好占卜師」與「維護用戶資料」的需求，可以定義一套標準輸出格式，讓 openclaw 的其他 Agent 或前端很容易接。

### 5.1 回應格式建議（結構）

每一次 opecclaw-FortuneTeller 的回答，可維持以下區塊：

1. 問題摘要（系統重新定義問題）
2. 占卜技術 \& 盤面 / 卦象 / 牌面說明（簡述）
3. 關鍵訊息（3–5 條 bullet）
4. 具體建議（行動導向）
5. 風險 \& 注意事項（例如：非醫療 / 法律建議）
6. 追蹤建議（建議何時回來做 follow-up）

### 5.2 中英示範骨架（以塔羅為例）

- 中文（使用者看到）

> 問題摘要：
> 你想了解未來三個月在工作上的發展與變化。
>
> 本次占卜：塔羅牌（三張牌陣：過去 / 現在 / 未來）
>
> 關鍵訊息：
> - 過去：權杖九（正位）——長期承受壓力，仍然咬牙撐住。
> - 現在：星幣二（正位）——需要在多項任務間保持彈性與平衡。
> - 未來：世界（逆位）——階段性成果可能延遲，需要調整目標或期待。
>
> 建議行動：
> 1. 先盤點目前手上的專案與責任，清楚列出優先順序。
> 2. 與主管或關鍵同事溝通你的負荷與期待，避免悶著頭硬撐。
> 3. 將「一定要達成」與「可以調整」的目標區分開來，降低挫折感。
>
> 提醒：占卜提供的是趨勢與建議，不是絕對結果，你的行動仍然可以改變未來。

- English（給 Agent / 系統記錄或未來國際化）

> Summary of question: Career development within the next 3 months.
> Method: Tarot, 3-card spread (Past / Present / Future).
> Insights: …
> Actionable advice: …

你可以在 openclaw 裡把這些欄位做成「Response Template」，每種技術掛同一套骨架，但細部內容由對應 skill 產生。
